# josephklane.com

Personal site for Joseph K. Lane. Hugo static site, deployed to Cloudflare.

## Structure

```
hugo.toml            site config, image processing, permalinks
archetypes/
  butterhut.md       front matter template for new Butterhut entries
content/
  _index.md          home (markup lives in layouts/home.html)
  butterhut/
    _index.md        project landing page
    site-work/
      index.md       one phase — photos live in this folder beside it
assets/css/main.css  all styling, shared by every page
static/headshot.jpg  640x720, masthead photo — served at /headshot.jpg
layouts/
  baseof.html        html/head/body shell and the theme toggle
  home.html          landing page markup, kept as originally hand-written
  section.html       /butterhut/ — the phase index
  page.html          a single phase page
  _partials/head.html  title, meta, canonical, JSON-LD
  _markup/render-image.html  markdown images -> responsive <figure>
public/              generated by Hugo — not in git
wrangler.jsonc       deploy config
```

Requires **Hugo 0.146 or newer** — `layouts/` uses the flat template lookup
(`home.html`, `page.html`, `section.html`, `_partials/`) introduced in that
release, not the older `_default/` and `partials/` paths.

```powershell
winget install Hugo.Hugo.Extended
```

## Writing

```powershell
hugo server            # http://localhost:1313, live reloads on save
hugo server -D         # include drafts
```

A new Butterhut entry is a folder, not a file:

```powershell
hugo new butterhut/roof-framing/index.md --kind butterhut
```

That creates `content/butterhut/roof-framing/index.md` with front matter
filled in. Drop photos into that same folder and reference them by bare
filename:

```markdown
![Batter boards at the uphill corner.](layout-strings.jpg "Diagonals were 3/4in out on the first pass.")
```

Hugo resizes each photo to the widths in `hugo.toml`, emits a `srcset`, writes
the real dimensions onto the tag, and re-encodes to webp — which also drops the
EXIF, including GPS.

Front matter that matters:

| Key      | Effect                                                            |
| -------- | ----------------------------------------------------------------- |
| `weight` | Position in the build order. The phase index sorts on this, not date. |
| `status` | `planned`, `in-progress`, or `complete`. Renders as a small tag.   |
| `lede`   | One-line summary, shown under the title and in the phase index.    |
| `draft`  | `true` hides it from a normal build. `hugo server -D` shows it.    |

Pages are organised by build phase rather than by date on purpose — dates
appear as small metadata, never as a page's identity.

For notes to yourself inside a content file, use the `comment` shortcode:

```markdown
{{< comment >}}
Never reaches the built site.
{{< /comment >}}
```

Not `<!-- ... -->`. Goldmark runs with `unsafe = true` so that raw HTML works
in markdown, which means an HTML comment passes straight through into the
served page — invisible in the browser, but sitting there in view-source.

## Deploying

Deployed to Cloudflare as an assets-only Worker, connected to this repo.

Configured in the Worker's **Settings → Build**:

```
Build command
  curl -sL https://github.com/gohugoio/hugo/releases/download/v0.164.0/hugo_extended_0.164.0_linux-amd64.tar.gz | tar xz && ./hugo --minify

Deploy command (production)      npx wrangler deploy
Deploy command (non-production)  npx wrangler versions upload
Root directory                   /
Non-production branch builds     enabled
```

Hugo is downloaded in the build command rather than relying on the build image
having it, so the version is pinned where you can see it. Bump the three
occurrences of the version number together. No `HUGO_VERSION` build variable is
needed — if one is set, it does nothing.

**Both deploy commands must be set.** `npx wrangler deploy` means "make this
live" and knows nothing about branches — with it as the only deploy command,
pushing *any* branch deploys to production. That is not hypothetical; it is how
this site first went live, from an unmerged branch. `wrangler versions upload`
gives non-production branches a preview URL instead.

Pushes to `main` deploy to josephklane.com. Other branches build to previews.

There is no Worker code — `wrangler.jsonc` has no `main` entry point, just an
`assets` directory pointed at `public/`, which is now Hugo's output rather than
hand-written files.

If production ever goes blank, that is what an empty `public/` looks like —
usually the build failing or the build command being cleared. Roll back in the
Worker's **Deployments** tab, then fix the build.

## Things not to break

- **`<link rel="canonical">` in the head.** Cloudflare serves this site at both
  `josephklane.pages.dev` and `josephklane.com`. The canonical tag is what stops
  those being treated as duplicate pages. It is now per-page (`.Permalink`).
- **The `Person` JSON-LD block.** It renders on the homepage only — repeating it
  site-wide would give several competing definitions of the same `@id`. The
  `sameAs` array should stay in sync with wherever profiles actually live; a
  dead link there is worse than no link.
- **Image dimensions.** The masthead `<img>` in `layouts/home.html` has hardcoded
  `width`/`height` that must match `static/headshot.jpg`, or the layout shifts as
  it loads. Content photos get theirs from Hugo and can't drift.
- **`publishDir`.** `hugo.toml` and `wrangler.jsonc` both have to agree that the
  built site lands in `public/`.

## Layout notes

The masthead intentionally spans wider (52rem) than the body copy (38rem). Body
text is held near a 75-character measure for readability; widening the text
column to match the header undoes that.

On Butterhut pages, photographs deliberately break out past the text measure to
the full 52rem column — a build log is carried by its images, and holding them
to the prose width makes them read as illustrations rather than as the subject.
